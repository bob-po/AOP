# 2026-09-25

## LangGraph 借鉴可行性分析（用户问：能否借鉴 LangChain/LangGraph 多智能体协作改造 AOP）
- 核对现状：Planner 产静态 skill DAG（`planner/__init__.py` PIPELINE + dag validation）；Executor = Redis Stream → route → A2A → unlock DAG
  （`executor/engine.py`），等价于 LangGraph 图执行的分布式版本。
- 已有 HITL：task 级 approve/reject（`main.py` `/v1/tasks/{id}/approve|reject`）+ 节点级 approve_node/reject_node（`scheduler/__init__.py`）。
- 结论（已告知用户）：
  - 借「协作语义/协议」，不借「框架/执行引擎」。不引入 langgraph 库（进程内 StateGraph 与跨进程 A2A OS 定位冲突）。
  - 值得借鉴四点：① 节点级 checkpoint 快照（细化 recovery 粒度）② interrupt/resume 带人类输入（现有 approve/reject 是二元决策）
    ③ 结构化 handoff payload（from/to/reason/artifact_refs/confidence → 写入 runtime_edges，前端协作图边可解释）
    ④ state reducer 语义 + 按节点裁剪上下文注入（append-only 与 overwrite 分离）。
  - 不借鉴：langgraph 库本身、MessagesState 全量 transcript 共享、裸 swarm 自由循环（与 governance/budget 冲突；要自主委托须配 max-depth + 递减预算）。
  - 前端机会：节点级快照 → 任务详情页时间旅行回放；handoff reason 显示在协作图边上；HITL 待审批队列。
